week 2 · four days · theme: the blueprint

Design patterns

The workflow patterns from the official LangGraph guide Workflows and agents, and the guardrails from the LangChain docs. Short code in the same style as the docs. Every day you build one pattern and measure what it costs, and on Day 4 you join them into one workflow and compare it with a plain agent.

Day1code

Chaining and routing

The augmented LLM (structured output and tools), then two patterns: a chain of steps with a gate between them (built twice: with the LangChain pipe, then with LangGraph), and a router that sends each question down the path that fits it. You measure what every path costs. Classwork (you build it yourself): a review sorter, a tweet chain with the LangChain pipe, and a support router with three paths.

  • Make the model answer in a class with with_structured_output
  • Build a chain with the LangChain pipe prompt | llm | parser, then the same chain with StateGraph and a conditional edge
  • Build a router with a search agent and a cheap direct path, and count the tokens

Day2code

Parallel work and orchestrator-worker

Three nodes look at one question at the same time, and an aggregator joins them. Then a planner writes the steps, Send starts one worker for each, and a reducer joins their notes into a brief. Classwork (you build it yourself): add a fourth side, and build a trip planner with one worker per day.

  • Run nodes in parallel with edges from START
  • Make a plan your code can read, and start one worker per step with Send
  • Join the notes of all the workers with a reducer

Day3code

Evaluator-optimizer

One call writes a draft from saved notes, another grades it with a clear rule and gives feedback, and the graph loops back until the draft passes, with a limit of three attempts. Classwork (you build it yourself): try to fool the evaluator, then build your own loop that improves an email.

  • Write an evaluator with a grade and feedback, and test it first
  • Build a loop: a conditional edge that goes back, and a limit
  • Measure what the loop costs, and decide when it is worth it

What we build, day by day

Day 1Chaining and routing

What we build
A chain with a length gate, and a router with two paths: a search agent and a direct answer.
Blocks used
init_chat_model, with_structured_output, bind_tools, StateGraph, conditional edges, create_agent with TavilySearch.
What you learn
Workflows and agents, state, nodes and edges, routing, and the token meter.

Day 2Parallel work

What we build
A parallel pros, cons and costs workflow, and a research workflow: a planner, one worker per step, and a writer.
Blocks used
Edges from START, Send, a reducer (operator.add), max_concurrency.
What you learn
When steps can run at the same time, plans you can read, and what a bigger plan costs.

Day 3Evaluator-optimizer

What we build
A write, grade and fix loop on saved notes, so nobody spends search tokens.
Blocks used
with_structured_output for the grade, a conditional edge that goes back, a limit in the state.
What you learn
Clear, checkable rules, loops with a limit, and when reflection is worth its tokens.

Day 4Guardrails and the project

What we build
A guarded agent, the research brief workflow with every pattern, and the eval table that tests it.
Blocks used
Llama Prompt Guard 2 (checked before the agent), PIIMiddleware, ToolCallLimitMiddleware, HumanInTheLoopMiddleware, a judge and a baseline agent.
What you learn
Guardrails of three kinds (input, output and execution), eval sets, and comparing with a baseline.

By the end of the week you have

  • A research workflow built from the patterns of the LangGraph docs: chaining, routing, parallel workers and an evaluator loop, protected by guardrails
  • An eval set and a judge, so you can prove that a change helped
  • A comparison with one plain agent, in numbers: helpful answers and tokens
  • A habit: add a pattern only when the table says it is worth its cost

Before you start

  1. You need the same two free keys as Week 1: Groq (console.groq.com → API Keys) saved as GROQ_API_KEY, and Tavily (tavily.com) saved as TAVILY_API_KEY.
  2. In Colab, click the 🔑 Secrets icon, add each key as a secret with the name above, paste the key, and switch Notebook access on.
  3. The free Groq plan has a speed limit (about 8,000 tokens a minute and 200,000 a day for each model). If a cell pauses, it is waiting for the limit. If it ends with a RateLimitError, wait one minute and run it again.
  4. Open the deck to follow along. In the deck: arrow keys move, F is fullscreen, Q shows likely questions, T switches to the chalkboard.
  5. Open the notebook in Colab and run the cells from top to bottom. Each TODO is real code with a few blanks (___) to fill in, and each check shows what you should see in its expected comments.
