Part 1 · Search, then read
Part 1 · Tool 1

Search finds. Extract reads.

query=topic

Only the useful parts

A page can have 95,000 characters, mostly menus. With the topic, Tavily returns about 2,000.

[:2500]

A hard cap

Keep at most 2500 characters. Every character costs tokens.

One try, one except

No if needed

Bad links raise errors. One except returns an Error: text. A good tool never crashes.

Questions that may come up0:13 to 0:17, then you code
Why only a snippet from search?
A search engine gives a summary of each result, not the page. The page text never reaches our program, so we need a second tool.
Why not one tool that does both?
Two small tools are easier to test, and the agent can skip the reading step when a snippet is enough.
What if the model invents a link?
extract_page returns an Error: text. The system prompt also says never to invent a link.
What does [:2500] mean?
Take only the first 2500 characters of the text, to keep the tokens we send to the model small.
Why is urls written as [url]?
Tavily can read many pages at once, so it expects a list, even for one link.
Why not check with if first?
The line after already fails in the bad cases: an unreachable link gives an empty list, so pages[0] raises an error. One except is shorter and catches cases we did not think of.
Isn't catching every Exception bad?
In big programs it can hide bugs. For a tool, the goal is to return a message the model can read, so it is the right trade.
Part 2 · Coordinates and weather
Part 2 · Tools 2 and 3

Coordinates, then weather

A weather service does not understand a city name. It wants a latitude and a longitude. Two jobs, two tools, both from Open-Meteo (free, no key).

The agent chains themThe second call needs the result of the first. The model reads the numbers from the text, and must never guess them.
Questions that may come up0:30 to 0:34, then you code
What are latitude and longitude?
Two numbers that locate a place on the globe: how far north or south, and how far east or west.
Why not one tool that takes a city?
Two small tools are easier to test, and the coordinates tool can be reused later, for example for distances.
Why does the docstring of get_weather mention get_coordinates?
The model reads the docstring. It learns that it must call get_coordinates first to get the numbers.
What if the model guesses the numbers?
The weather would be for the wrong place. The system prompt says never to guess coordinates.
Why float for the inputs, and why round to 2 decimals?
Latitude and longitude have decimals. Two decimals is about one kilometre, which is enough for the weather and keeps the text short.
Why str(latitude)?
You cannot join a number to text with +. str() turns the number into text.
Why timeout=10?
If the service does not answer in 10 seconds, the request stops and the except returns an Error. Otherwise the agent could wait forever.
Can two tools run at the same time?
Yes, when neither needs the other's result. The agent can ask for the weather and the currency in one step.

Why .upper()?
So that "usd" and "USD" both work. The model sometimes writes lowercase codes.
Does it support Nepali rupees?

Is the rate live?

Can't a good model do simple maths?
Often yes, but it is not guaranteed. A tool is exact every time and costs almost nothing.
Why test a tool by hand first?
It is far easier to fix a tool alone than inside an agent, where many things can go wrong at once.

Questions that may come up0:55 to 1:00, then you code
Why so many rules?
Each rule guards against a mistake models can make: guessing coordinates, inventing links, asking for tools that do not exist, or adding old years to a search.
Why include today's date?
A model does not know the date. Without it, it adds old years to the search words.
Is a longer prompt always better?
No. Every line should fix a problem you have seen. Test, then add a rule.
Does the model read my code?
No. It sees only the tool's name, the docstring and the inputs.
What if two tools sound the same?
The model may pick the wrong one. Make each docstring clearly different.
Why doesn't the agent print each step like Day 2?
To keep the output short. The Tools used line in the tests gives you the order of the tools without extra noise.
Where does Tools used come from?
From the messages of the run: every message of type tool is a tool result, and it has the tool's name.
The agent asked for a tool that does not exist.
The model made a mistake. The cell prints Stopped early. Run it again.

Questions that may come up1:10 to 1:17, then you code
What counts as a step?
Each trip between the model and the tools. Chained tools use more steps, which is why the limit is 12 today.
What if 12 is not enough?
The agent stops and prints Stopped early. Raise it a little, but ask why it needed so many steps.
Does memory cost anything?
Yes. The old messages are sent again each turn, so long chats use more tokens.
What happens if I restart the notebook?
The memory is gone. InMemorySaver keeps it only in the computer's memory.
Where is thread_id written?
In the config: thread_id sits inside configurable, and recursion_limit is beside it.
Why the same questions for everyone?
So we can compare results and fix a common problem once.
What if the page was not useful?
Change the search words in the question, or let the agent try one other link, as the prompt says.
Why does the search sometimes fail?
The free DuckDuckGo search refuses requests when many are made at once. The tool tries twice, and then returns an Error: text. Wait a little and run again.
A different answer each run. Is it broken?
No. The model and the web change between runs. The numbers should match, the wording will not.
Rate limit message?
Free key limit. Wait a minute, then run again.
