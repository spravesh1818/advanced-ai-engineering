Questions that may come up0:16 to 0:18
Orchestration vs the agent loop?
Orchestration is the broad word for coordinating the parts. A fixed workflow, an agent loop, or a supervisor managing several agents are all kinds of orchestration.
State vs memory?
State is what the agent knows during one run. Memory (Week 3) is what is saved between runs.
Trajectory vs a log?
A trajectory is the log of an agent's steps: what it decided, which tool it called, and what came back.

Questions that may come up0:24 to 0:27
It can write code. Doesn't that count as an action?
Writing code is just text. Running that code is an action and needs a tool.
Can't I just paste the data into the prompt?
Yes, for simple cases. But then you decide what data is needed. An agent decides for itself when and what to fetch.
What is 4,817 × 2,936, then?
14,142,712. A calculator tool gets this exactly every time; a model guessing digits might not.
Can an LLM check its own work?
It can try if asked (a pattern called reflection, Week 2), but a single call has no second pass built in.
The problem
The fix

Give the model tools

Example"Weather in Pokhara?" → model asks get_weather("Pokhara") → code calls the API → 21°C, clear → "It's 21°C and clear."

The model only asks. Your code does the work, then hands the result back. (Built-in tools, like a provider's web search, run on the provider's servers instead; the idea is the same.)

Questions that may come up0:27 to 0:30
So the AI doesn't run code?
Correct. Your program does. That's also a safety feature: you control what can run.
How does the model know what tools exist?
We list them in the request with names, descriptions, and parameters. You'll see this on Day 2.
Is this the same as "function calling"?
Yes. Tool calling and function calling mean the same thing here.
Do all tools run in our own code?
Your own tools do. Some providers also offer built-in tools, like Groq's browser search, that run on their servers. The idea is the same: the model asks, something runs it, and the result comes back.
LLM · Workflow · Agent
Three shapes of an AI system

LLM call → Workflow → Agent

01 · LLM call

One step

One prompt in, one answer out. No loop.

e.g."Translate this sentence into Nepali."
02 · Workflow

You set the steps

Fixed path, always the same order. The LLM is one step in it.

e.g.Every night: summarise new tickets, then email the team.
03 · Agent

The model decides

Picks tools and next steps itself, looping until finished.

e.g."Find a flight to Delhi under $200 and book it."

Ask at every system: who decides what happens next?  Nobody · You · The model

Questions that may come up0:30 to 0:34
Is a workflow with an LLM still "AI"?
Yes. It uses an LLM, but you wrote the path.
What if the workflow has an if/else?
Still a workflow. The branching rules are yours, written in advance.
Is Zapier (or n8n) a workflow?
Yes. They are workflow builders, and many now include LLM steps.
Why is the flight example an agent?
The model has to search, compare, maybe search again, then decide to book. You can't fix those steps in advance.
LLM · Workflow · Agent
An everyday picture

Two kinds of employee

Workflow

The checklist employee

"Do step 1, then step 2, then step 3." Same result every time.

+ Predictable   + Cheap   + Easy to test
− Gets stuck on anything unexpected
Best forMaking the monthly salary slips
Agent

The "get it done" employee

"Here's the goal. Figure it out." Chooses the steps, adapts to surprises.

+ Flexible   + Handles the unexpected
− Costs more   − Less predictable   − Can go wrong
Best forPlanning a 3-day trip on a fixed budget

Questions that may come up0:34 to 0:36
Which one is cheaper?
Usually the workflow: fewer model calls and no wandering.
Can a workflow ever handle surprises?
Only the ones you planned for in advance.
Can I combine them?
Yes. Many real systems are workflows with one agent step inside.
Would you give a new employee full freedom to move money?
No, and that's the risk side of autonomy. Trust (and freedom) is earned step by step.

Anatomy of an agent
The LLM is the brain

Four parts make it an agent

1

Loop

Think, act, observe, repeat.

e.g.Keeps going until both cities are checked
2

Tools

The actions it is allowed to ask for.

e.g.get_weather(), search()
3

State

What it has done and learned so far.

e.g."Kathmandu = 18°C" is saved
4

Stop

The rule for when to finish.

e.g.Answer is ready, or 10 steps used

All four are needed for a reliable agent. Week 1 builds all four. Examples are from the weather agent we build on Day 2.

Questions that may come up0:57 to 1:00
Where does the LLM fit in these four?
It's the thinker inside the loop. The four parts surround it.
Can an agent exist without tools?
It would just be a model talking to itself. Tools are what let it see or change the world.
Is "stop" the same as the final answer?
Related but not the same. Stop is the rule that decides when to finish, for example the model answers without asking for a tool, or a step limit is reached.

Reality check
Failure modes

Why agent projects fail

1

Too much autonomy

A workflow would have been enough, and more reliable.

e.g.An agent to rename 100 files. A 5-line script does it perfectly.
Fix: start low, climb only when needed.
2

No evaluation

"It seemed fine in the demo" is not a quality bar.

e.g.Passed 2 test questions, failed the first real user.
Fix: test on real questions, many times.
3

Invisible failures

No logs of what it did, so nobody knows why it failed.

e.g.Gave a wrong price, and nobody can see which search it used.
Fix: record every step (trajectory).
Questions that may come up1:12 to 1:18
How do we evaluate an agent?
Start with a list of real test questions and check the answers, many times. Proper evaluation comes in Week 5.
What does an "invisible failure" look like?
The agent gives a wrong answer and you can't tell which step went wrong, because nothing was recorded.
Do big companies have this problem too?
Yes, it's very common. That's why logging and testing matter so much.
Before we build
Three practical things

Tokens, limits, keys

Tokens

Pieces of text

Models read and write in tokens, roughly ¾ of a word each in English. Cost and limits are counted in tokens.

e.g.100 words ≈ 130 tokens
Rate limits

Error 429

Free tiers allow only so many requests per minute. Too many gives a "slow down" error. Agents loop, so they hit it faster.

e.g.30 calls in a few seconds → 429
API keys

Treat as a password

Keep it in a .env file. Never paste it into code, slides, screenshots, or chat.

e.g.A key pushed to GitHub can be found and used by strangers
Questions that may come up1:18 to 1:23
Why do agents hit limits faster?
Each loop is another request, and the history gets longer every time.
What does 429 mean?
"Too Many Requests." Wait a little and retry. We handle this in code in Day 3.
I shared my key in a screenshot. What now?
Delete that key in the Groq console and create a new one. Anyone with the old key could use your account.
Is "¾ of a word" exact?
No, it's a rule of thumb for English. Other languages and code often use more tokens per word.
